# 면접용 ML 경험 정리

## 60초 소개

“화학공정 센서 시계열에서 결함을 조기에 찾는 프로젝트를 했습니다. 78만 행처럼 보이지만 실제 독립 결함 이벤트는 35개뿐이라 이벤트 단위로 분할하고 실시간 특징을 인과적으로 구성했습니다. 탐지율 100%와 반응기 1대·24시간당 오탐 1건 이하를 제약으로 두고 HGB로 Test 중앙 지연을 68.5분에서 30분으로 56% 줄였습니다. 이후 전체 90일 재생에서는 오탐이 1.31건/반응기·24시간이라 배포를 보류했습니다. 결함 유형은 온라인 Extra Trees로 매분 갱신했고 Test 8개에서 경보 즉시 7개, 10분 후 8개를 맞혔지만 표본과 신뢰도 한계 때문에 작업자 보조로 한정했습니다.”

## 내가 직접 설명해야 할 핵심 결정

### 왜 HGB였나?

로지스틱 회귀는 해석 가능한 기준선이지만 센서 간 비선형 상호작용에 약했다. Extra Trees는 강한 표 데이터 기준선이었지만 확률이 계단형이고 약한 초기 추세에 상대적으로 늦었다. HGB는 앞 트리의 오차를 순차 보완해 6시간 기준선 대비 작은 변화 조합을 더 빨리 포착했다. Validation에서 HGB 30.5분, Extra Trees 40.5분, 로지스틱 50.5분이었고 모두 탐지율 100%와 오탐 예산을 만족해 HGB를 선택했다.

### 왜 딥러닝을 쓰지 않았나?

78만 행은 시간적으로 강하게 상관되어 있고 독립 결함 이벤트는 35개뿐이다. 행 수만 보고 LSTM이나 Transformer를 쓰면 실제 표본 수를 과대평가하고 과적합할 가능성이 높다. 그래서 작은 이벤트 수에서 검증 가능한 트리 모델과 명시적 시계열 특징을 우선했다.

### 오탐과 미탐을 어떻게 다뤘나?

미탐 비용이 큰 설비 결함 문제라 이벤트 탐지율 100%를 먼저 제약으로 두었다. 그 안에서 반응기 1대·24시간당 정상 오탐 예산을 정하고 탐지 지연을 최소화했다. 기존 모델은 미탐 0·오탐 0이지만 68.5분 늦었고, HGB는 미탐 0을 유지하면서 오탐 0.875건/반응기·24h를 허용해 30분으로 줄였다. 이후 전체 연속 재생에서 1.308건/반응기·24h가 나와 이벤트 주변 평가가 낙관적이었음을 확인하고 배포를 보류했다.

### 데이터 누출은 어떻게 막았나?

- 같은 결함 이벤트의 앞뒤 시점을 서로 다른 split에 넣지 않았다.
- 결함 유형별 미래 이벤트를 validation/test로 남겼다.
- `fault_type`, `time_to_fault_min`, `efficiency_loss_pct`를 입력에서 제외했다.
- 실시간 결측은 미래값을 쓰는 선형 보간 대신 forward fill을 사용했다.
- rolling 기준선은 현재값도 제외했고 모든 연산을 반응기별로 수행했다.
- 모델·임계값·연속 조건은 validation에서만 골라 test에 고정했다.

### PR-AUC만으로 모델을 고르지 않은 이유는?

PR-AUC는 불균형 분류의 순위 품질을 보여주지만 실제 경보 횟수나 첫 탐지 시점을 직접 답하지 않는다. 같은 PR-AUC라도 임계값과 연속 조건에 따라 작업자가 받는 경보량과 대응 가능 시간이 달라진다. 그래서 PR-AUC는 보조 지표로 두고 이벤트 탐지율, 오탐/반응기·24h, 중앙 지연으로 최종 선택했다.

## 실패와 수정 경험

1. 처음 Extra Trees는 이벤트 주변 평가에서 오탐 0건이었지만 Test 지연이 68.5분이었다.
2. 6시간 인과적 기준선 특징과 HGB를 도입해 지연을 30분으로 줄였다.
3. EWMA를 더한 빠른 후보는 validation에서 28.5분이었지만 90일 재생 오탐이 1.544건/반응기·24h로 악화돼 기각했다.
4. 결함별 물리 규칙은 설명 가능했지만 힌트 정확도 57.1%, 결합 오탐 3.75건/반응기·24h라 경보 트리거로 쓰지 않았다.
5. 결과적으로 하나의 민감한 경보 대신 이상 징후·조기 경고·확정 경보를 분리해 행동 비용에 맞췄다.
6. 10분 목표도 별도로 검증했다. 중앙 지연만 8.5분으로 만들 수는 있었지만 10분 내 5/8 탐지에 오탐 41건/반응기·24h였고, 8/8을 강제하면 98건/반응기·24h여서 채택하지 않았다.
7. 경보 병합만으로 해결되는지도 확인했다. 60분 cooldown과 30분 해제 대기에도 약 10.3건/반응기·24h였고, 대신 반응기별 24시간 상대 변화 점수를 shadow 신호로 두자 8/8 탐지와 0.29건/반응기·24h를 유지했지만 중앙 지연은 35분이었다.

면접에서는 “성능을 계속 올렸다”보다 “어떤 가설을 검증했고, 어떤 수치 때문에 채택·기각했는지”를 이 순서로 말하는 것이 좋다.

## 예상 꼬리 질문

**Test 100% 탐지·분류면 좋은 모델 아닌가?**

이진 탐지는 8/8이었다. 집계형 유형 모델은 6/8이었지만 온라인 방식으로 다시 설계해 경보 즉시 7/8, 10분 후 8/8이었다. 그래도 유형별 Test가 2개이고 신뢰도가 낮아 100%를 안정적인 일반화 성능으로 해석하지 않았다.

**전체 재생의 중앙 지연 1분은 왜 보고하지 않나?**

전체 35개에는 학습·검증 이벤트가 포함돼 독립 평가가 아니다. 이 재생은 장기 오탐과 스트리밍 파이프라인을 점검하는 엔지니어링 감사에만 사용했다.

**왜 F1이 늦었나?**

냉각 성능 저하는 급격한 점프보다 완만한 추세로 나타나 정상 레짐 변화와 구분하기 어렵다. Test 두 이벤트의 중앙 지연이 61.5분이고 하나는 90분이었다. 추가 실측 이벤트와 더 긴 기준선, 레짐별 calibration을 검토하되 현재 표본으로 전용 모델을 분리하지는 않았다.

**레짐별 모델을 따로 만들지 않은 이유는?**

레짐 A Test가 2개뿐이고 개별 모델은 B에서 지연을 68.5분에서 58.5분으로 줄였지만 오탐이 1.167건/반응기·24h로 늘었다. 근거가 부족해 통합 조건부 모델과 공통 규칙을 유지했다.

**다음에 무엇을 개선하겠나?**

새 기간·새 반응기의 완전 독립 데이터 확보가 우선이다. 그다음 bootstrap 기반 이벤트 신뢰구간, reactor holdout, 온라인 유형 확률 calibration과 시간적 안정화, drift 감시, 경보 hysteresis·cooldown을 검증하겠다.

**10분 탐지는 불가능한가?**

절대 불가능하다고 결론 내린 것은 아니다. 현재 센서와 오탐 예산에서는 근거가 없다는 뜻이다. 임계값을 낮추는 대신 향후 10~30분 결함을 예측하는 사전 경보 레이블, 더 이른 제어기 신호, 반응기별 변화점 특징을 새 데이터에서 검증해야 한다.

**1분마다 추론해서 오탐이 과장된 것 아닌가?**

연속 양성 분을 각각 세지 않고 하나의 경보 에피소드로 묶었다. 추가로 hysteresis와 cooldown도 검증했지만 민감 후보는 10건/반응기·24h 이상이었다. 추론 주기와 사용자 알림은 분리해야 하며, 실제 알림에는 incident 병합 정책을 적용한다.

**결함 유형은 어떤 패턴으로 구분했나?**

F1은 온도 상승과 냉각수 감소, F2는 원료 유량과 전환율 감소, F4는 진동과 모터 전류 상승이 핵심이었다. F3는 온도 변화만 보고 판단하지 않고 관련 공정 변수와의 불일치를 봤다. 다만 물리 규칙의 유형 힌트 정확도가 57.1%라 경보 트리거가 아닌 설명 정보로만 사용했다. 세부 수치는 [결함 유형별 패턴](./fault_pattern_guide.md)에 정리했다.

## 최종 면접 메시지

“처음에는 모델 성능을 높이는 데 집중했지만 실제로 중요한 것은 독립 이벤트 기준 지연, 경보량, 진단 가능 시간이었습니다. HGB로 이진 탐지 지연을 56% 줄였고 10분 탐지는 오탐 비용 때문에 기각했습니다. 느린 집계형 유형 모델은 매분 갱신하는 온라인 모델로 다시 설계해 F1·F3 구분 가능성을 확인했습니다. 다만 작은 Test와 낮은 신뢰도를 숨기지 않고 배포를 보류했습니다. 가장 큰 성과는 높은 숫자보다 평가 누수를 막고 채택·중단 기준을 수치로 만든 것입니다.”

## 과장하지 말아야 할 표현

- “운영 배포했다” → “배포 전 연속 재생까지 검증했고 목표 미달로 보류했다.”
- “78만 개 독립 샘플” → “78만 시점, 독립 결함 이벤트 35개.”
- “유형 분류 정확도 100%를 달성했다” → “경보 10분 시점의 8개 이벤트에서 8/8이었지만 표본과 확률 신뢰도가 부족했다.”
- “CUSUM 모델을 학습했다” → “기존 HGB 점수에 CUSUM 경보 후처리를 적용했다.”
- “실제 공장 데이터” → “화학공정을 모사한 합성 데이터.”
