# 화학공정 조기 이상 탐지 프로젝트

## 한 줄 요약

6개 반응기의 1분 주기 합성 시계열 777,600행에서 **1단계 HGB로 결함 여부를 탐지하고 2단계 온라인 Extra Trees로 F1~F4 유형 확률을 매분 갱신하는 파이프라인**을 설계했다. 이벤트 단위 분할, 인과적 특징, 운영 제약 기반 모델 선택, 90일 연속 재생까지 수행했으며, 장기 오탐 목표를 넘은 모델은 배포하지 않고 개발 기준선으로 남겼다.

## 문제와 평가 기준

- 과제: 정상/결함 이진 탐지 후 F1~F4 결함 유형 분류
- 데이터: 35개 결함 이벤트, train 19 / validation 8 / test 8
- 핵심 지표: 이벤트 탐지율, 결함 시작 후 중앙 탐지 지연, 반응기 1대·24시간당 정상 오탐
- 보조 지표: PR-AUC, ROC-AUC, 결함 유형 macro F1
- 운영 목표: 탐지율 100%를 유지하고 오탐 예산 안에서 지연 최소화

오탐률은 `전체 정상 경보 에피소드 ÷ 전체 정상 반응기 시간`으로 계산한 **반응기 1대·24시간당 경보 수**다. 6개 반응기의 공장 하루 총 알림량은 이 값과 다르며, 모든 반응기가 가동 중이라면 대략 6배가 될 수 있다.

행 단위 무작위 분할은 같은 이벤트의 인접 시점이 학습과 평가에 섞이므로 사용하지 않았다. 결함 유형별 시간 순서에 따라 이벤트 전체를 분리했고, 모델과 경보 규칙은 validation에서 정한 뒤 test에 고정했다.

## 데이터·특징 설계

- 결측은 약 6%, 결측 구간의 99.63%가 1~2분, 최장은 6분이었다.
- 오프라인 분석은 최대 6분 선형 보간, 실시간 입력은 미래를 쓰지 않는 최대 6분 forward fill로 구분했다.
- 정답성 컬럼 `fault_type`, `time_to_fault_min`, `efficiency_loss_pct`는 입력에서 제외했다.
- 반응기별 현재값, 1·5·15·30·60분 변화량, 5·15·60분 이동 통계, 설정값 편차와 센서 비율을 만들었다.
- 느린 결함을 잡기 위해 현재를 제외한 과거 6시간 기준 z-score와 15분 평균 대비 기준선 차이 24개를 추가해 총 176개 특징을 사용했다.

모든 특징은 현재와 과거만 사용하며 반응기 경계를 넘지 않는다. 이 설계는 정확도보다 실제 스트리밍에서 동일하게 재현되는지를 우선한 선택이다.

## 모델 비교와 선택

Validation에서 탐지율 100%, 오탐 1건/반응기·24시간 이하인 설정 중 중앙 지연이 가장 짧은 조합을 선택했다.

| 모델 | 중앙 지연 | 오탐/반응기·24h | PR-AUC | 선택 해석 |
|---|---:|---:|---:|---|
| Histogram Gradient Boosting | 30.5분 | 0.75 | 0.945 | 비선형 센서 조합과 약한 초기 신호에 가장 빠름 |
| Extra Trees | 40.5분 | 0.25 | 0.937 | 오탐은 적지만 초기 신호 반응이 느림 |
| Logistic Regression | 50.5분 | 1.00 | 0.925 | 해석 가능한 기준선이나 선형 경계의 한계 |

HGB와 `threshold=0.35`, 2분 연속 조건을 선택했다. 독립 시퀀스가 35개뿐이어서 LSTM·Transformer는 과적합 위험이 크다고 판단해 제외했다.

## Test 결과와 오탐·미탐

| 항목 | 기존 Extra Trees | 최적화 HGB |
|---|---:|---:|
| 이벤트 탐지율 | 8/8, 100% | 8/8, 100% |
| 미탐 이벤트 | 0 | 0 |
| 중앙 탐지 지연 | 68.5분 | 30.0분 |
| 이벤트 주변 오탐/반응기·24h | 0.000 | 0.875 |
| 지연 개선 | 기준 | 56.2% 감소 |

HGB는 오탐을 일부 허용해 지연을 줄였다. 유형별 중앙 지연은 F1 61.5분, F2 31분, F3 36분, F4 17.5분이었다. 특히 F1의 한 이벤트는 90분이 걸려 냉각 성능 저하와 같은 느린 결함이 약점으로 남았다.

단, 이벤트 주변 24시간 표본의 오탐률은 낙관적일 수 있었다. 전체 90일을 재생하자 HGB 기준선은 정상 오탐 1.308건/반응기·24h, 더 빠른 후보는 1.544건/반응기·24h로 목표 1건을 모두 초과했다. 따라서 빠른 후보는 기각하고 HGB도 배포 모델이 아닌 개발 기준선으로 유지했다. 전체 35개 이벤트의 1분 중앙 지연은 학습 이벤트가 섞인 비독립 결과라 성능 수치로 사용하지 않는다.

## 결함 유형 분류

30분 집계 모델의 지연을 해결하기 위해 HGB 경보 이후 매분 F1~F4를 출력하는 Extra Trees를 다시 설계했다. 24개 6시간 기준 특징과 냉각·온도 불일치 등 5개 물리 관계 특징을 사용했다. Validation 초기 시점 평균 macro F1으로 선택했으며, 경보 즉시 Test macro F1은 0.867, 10분 후는 1.0이었다. 10분 시점에 F1과 F3도 구분했지만 Test가 유형별 2개이고 신뢰도가 낮아 실시간 작업자 보조용 prototype으로 유지했다.

## 운영 정책 실험

- 이상 징후: 26.5분, 정상 경보 4.612건/반응기·24h — 화면 표시만
- 조기 경고: 29.5분, 1.936건/반응기·24h — 작업자 확인
- 확정 경보: 32분, 0.957건/반응기·24h — 대응 절차 시작
- 결함별 물리 규칙: 힌트 정확도 0.571, 결합 오탐 3.75건/반응기·24h라 트리거로 기각하고 설명용으로만 유지
- CUSUM: HGB 확률의 log-odds를 누적하는 후처리 후보. 독립 Test 중앙 지연 34분, 전체 재생 오탐 0.774건/반응기·24h이며 새 모델이 아니라 경보 규칙으로 해석

## 최종 판단과 한계

가장 중요한 결과는 높은 Test 점수가 아니라 배포 보류 결정이다. 합성 데이터, 35개 이벤트, Test 8개라는 한계가 있고 연속 재생에서 장기 오탐 목표도 넘었다. 다음 단계는 새로운 기간·반응기의 외부 검증, 경보 해제 hysteresis와 억제 시간, 온라인 유형 확률 calibration과 시간적 안정화다.

### 10분 탐지 목표 재검증

현재 HGB에서 임계값 0.01·1분 조건은 Test 중앙 지연 8.5분이지만 10분 내 탐지는 5/8, 전체 정상 오탐은 41.0건/반응기·24h였다. 8/8을 강제로 잡으려면 임계값 약 0.0015가 필요했고 오탐이 98.3건/반응기·24h까지 증가했다. 초기 10분 전용 HGB 재학습도 Validation 전 이벤트 탐지와 낮은 오탐을 동시에 만족하지 못했다. 따라서 현재 센서에서는 10분 확정 경보를 기각하고, 사전 예측 레이블과 더 이른 물리 신호를 확보하는 문제 재설계를 다음 단계로 정했다.

현실적인 incident 병합도 검증했다. 임계값 0.01 후보에 60분 cooldown과 30분 경보 해제 대기를 적용해도 약 10.3건/반응기·24시간이었다. 반면 직전 24시간의 반응기별 HGB log-odds 대비 상대 z-score와 2-of-3 조건은 Validation·Test 8개를 모두 탐지하면서 정상 경보 0.29건/반응기·24시간, Test 중앙 지연 35분이었다. 더 빠르지는 않지만 오탐이 적어 모델 교체가 아닌 shadow-mode 확인 신호로 남겼다.
