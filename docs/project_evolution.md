# 프로젝트 발전 과정과 의사결정 기록

## 출발점

이 프로젝트는 화학공정 시계열에서 결함을 탐지하고 F1~F4 유형을 분류하는 문제로 시작했다. 처음부터 높은 행 단위 정확도보다 다음 질문에 답하는 것을 목표로 했다.

- 결함 이벤트를 놓치지 않는가?
- 결함 시작 후 몇 분 만에 경보하는가?
- 정상 운전 중 작업자가 받는 잘못된 경보는 얼마나 되는가?
- 실제 스트리밍에서도 같은 전처리와 특징을 사용할 수 있는가?

## 1. 데이터 이해와 누출 방지

EDA에서 777,600개 시점, 6개 반응기, 두 운전 레짐과 35개 결함 이벤트를 확인했다. 행은 많지만 독립 결함 사례는 35개뿐이라는 점이 이후 모든 모델 선택의 기준이 됐다.

결측은 약 6%였고 99.63%가 1~2분, 최장은 6분이었다. 오프라인 분석에는 선형 보간이 더 정확했지만 미래값을 사용하므로, 실시간 모델에는 반응기별 최대 6분 forward fill을 선택했다. 정답성 정보인 `fault_type`, `time_to_fault_min`, `efficiency_loss_pct`는 입력에서 제외했다.

같은 이벤트의 인접 행이 train과 test에 섞이지 않도록 결함 이벤트 전체를 시간 순서에 따라 train 19개, validation 8개, test 8개로 분리했다.

## 2. 결함 패턴 탐색

처음에는 결함 발생 6~24시간 전부터 뚜렷한 전조가 있을 것으로 기대했다. 그러나 33개 분석 가능 이벤트에서 반복 가능한 큰 변화나 변동성 증가는 거의 없었다. 이 결과로 문제를 장기 고장 예측보다 **결함 발생 이후 빠른 탐지**에 맞췄다.

결함 시작 후에는 유형별 조합이 나타났다.

- F1: 반응기 온도 상승 + 냉각수 유량 감소
- F2: 원료 유량 감소 + 전환율 감소
- F3: 온도 측정값 변화 + 관련 공정 변수와의 불일치
- F4: 진동 RMS 상승 + 모터 전류 상승

단일 센서 임계값보다 물리적으로 연결된 센서 조합을 특징으로 사용하는 방향을 잡았다.

## 3. 실시간 특징과 첫 기준 모델

매분 현재값과 과거값만 이용해 변화량, 이동평균·표준편차, 설정값 편차와 센서 비율 등 152개 특징을 만들었다. 모델은 1분마다 결함 확률을 출력하지만 성능은 독립 이벤트별 탐지 여부와 최초 경보 지연으로 평가했다.

첫 비교에서는 Logistic Regression보다 Extra Trees의 PR-AUC가 높았다. Validation에서 확률 임계값 0.25와 3분 연속 조건을 선택했다.

- Test 이벤트 탐지: 8/8
- 이벤트 주변 오탐: 0건
- 중앙 탐지 지연: 68.5분

미탐과 오탐은 없었지만 경보가 지나치게 늦다는 문제가 남았다.

## 4. 탐지 속도 최적화

느린 변화와 정상 레짐 차이를 구분하기 위해 직전 6시간 기준 z-score와 15분 평균 대비 기준선 차이 24개를 추가했다. Logistic Regression, Extra Trees, Histogram Gradient Boosting을 같은 조건에서 비교했다.

Validation에서 모든 이벤트 탐지와 오탐 1건/반응기·24시간 이하를 제약으로 두고 중앙 지연을 최소화한 결과, HGB의 임계값 0.35와 2분 연속 조건을 선택했다.

- Test 이벤트 탐지: 8/8
- 중앙 탐지 지연: 30분
- 이벤트 주변 오탐: 0.875건/반응기·24시간
- 기존 대비 지연 감소: 56.2%

딥러닝은 사용하지 않았다. 78만 행이 있어도 독립 이벤트가 35개뿐이라 LSTM·Transformer의 과적합 위험이 크다고 판단했다.

## 5. 좋은 오프라인 결과를 다시 의심함

이벤트 주변 24시간 표본의 오탐률은 실제 장기 운전을 낙관할 수 있었다. 두 모델을 6개 반응기의 전체 90일 데이터에 재생했다.

- 현재 HGB: 1.308건/반응기·24시간
- 더 빠른 EWMA 후보: 1.544건/반응기·24시간
- 목표: 1건/반응기·24시간 이하

빠른 후보를 기각했고 HGB도 배포 모델이 아닌 개발 기준선으로 남겼다. 전체 재생에서 나온 1분 중앙 지연은 학습 이벤트를 포함한 비독립 결과이므로 성능으로 보고하지 않았다.

## 6. 결함 유형 진단과 물리 규칙

처음에는 이전 Extra Trees 경보 이후 60분 Logistic Regression을 선택해 Test 8개를 모두 맞췄지만 최종 HGB 경보 시점과 맞지 않았다. HGB 기준 30분 집계 모델은 Test macro F1 0.75였고 여전히 늦었다. 이후 집계를 제거하고 경보 이후 매분 유형을 갱신하는 Extra Trees를 설계했다. 냉각 패턴과 온도-공정 불일치 특징을 추가한 결과 Test는 경보 즉시 macro F1 0.867, 10분 후 1.0이었으며 F1·F3도 구분했다. 다만 유형별 Test가 2개이고 신뢰도가 낮아 작업자 보조용 prototype으로 한정했다.

결함별 물리 규칙도 만들었지만 유형 힌트 정확도는 57.1%, 결합 오탐은 3.75건/반응기·24시간이었다. 따라서 규칙을 경보 트리거로 사용하지 않고 경보 이후 원인 설명에만 사용하기로 했다.

## 7. 하나의 경보를 세 단계로 분리

속도와 오탐 중 하나만 고르는 대신 경보가 유발하는 행동에 따라 단계를 나눴다.

| 단계 | Test 중앙 지연 | 정상 경보/반응기·24h | 행동 |
|---|---:|---:|---|
| 이상 징후 | 26.5분 | 4.612 | 화면 표시·관찰 강화 |
| 조기 경고 | 29.5분 | 1.936 | 작업자 확인 |
| 확정 경보 | 32분 | 0.957 | 대응 절차 시작 |

모델 추론은 1분마다 수행하지만 연속된 양성 분을 각각 오탐으로 세지 않았다. 확률 임계값과 persistence를 만족해 생성된 연속 경보 구간을 하나의 에피소드로 평가했다.

## 8. 10분 탐지 목표 재검증

더 빠르게 탐지할 수 있는지 확인하기 위해 임계값을 낮추고 초기 10분 전용 재학습도 시도했다.

| 후보 | 10분 내 탐지 | 중앙 지연 | 정상 경보/반응기·24h |
|---|---:|---:|---:|
| 임계값 0.01, 1분 | 5/8 | 8.5분 | 41.0 |
| 임계값 0.0015, 1분 | 8/8 | 0.5분 | 98.3 |
| 임계값 0.0015, 2분 | 7/8 | 2.5분 | 53.9 |

10분이라는 수치는 만들 수 있었지만 작업자가 사용할 수 없는 경보량이었다. 초기 10분을 강조한 HGB도 Validation 전 이벤트 탐지와 낮은 오탐을 동시에 만족하지 못했다. 현재 센서에서는 초기 결함과 정상 변동이 겹친다는 결론을 내렸다.

## 9. 오탐 정의와 실제 incident 정책

“1분마다 추론하므로 오탐이 과장된 것 아닌가?”라는 질문에서 경보 계산을 다시 점검했다. 기존 오탐은 매분 양성을 센 것이 아니라 연속 양성 구간을 한 건으로 센 값이었다. 그래도 짧은 정상 복귀 뒤 재발한 경보를 합치기 위해 hysteresis와 cooldown을 적용했다.

임계값 0.01 후보에 60분 cooldown과 30분 정상 유지 후 해제를 적용해도 약 10.3건/반응기·24시간이었다. 현실적인 incident 병합은 필요하지만, 그것만으로 10분 탐지와 1건/반응기·24시간 이하를 동시에 달성하지는 못했다.

## 10. 오탐이 적은 보조 확인 신호

절대 확률 대신 반응기별 직전 24시간 HGB log-odds에서 얼마나 벗어났는지 계산했다. 정상 상위 0.1% 임계값과 최근 3분 중 2분 조건을 사용한 상대 변화 후보의 결과는 다음과 같다.

- Validation 탐지: 8/8
- Test 탐지: 8/8
- Test 중앙 지연: 35분
- 정상 경보: 0.29건/반응기·24시간
- 10분 내 탐지: 0/8

속도를 개선하지는 못했지만 오탐이 적어, 기존 모델을 교체하지 않고 shadow-mode 확인 신호로 남겼다.

HGB 다단계 경보를 개발 기준선으로 유지하고 상대 변화 점수는 shadow-mode 확인 신호로 남겼다.

## 11. 결함 유형 분류를 실시간으로 전환

30분 집계형 유형 모델도 대응에 늦다는 문제를 다시 제기했다. 경보 이후 집계를 기다리지 않고 매분 F1~F4 확률을 갱신하도록 학습 단위를 이벤트 집계에서 분 단위 온라인 시점으로 바꿨다.

- 입력: 6시간 기준 특징 24개 + 냉각·온도 불일치 등 물리 관계 특징 5개
- 모델 선택: Validation의 경보 후 0·5·10·15분 macro F1 평균
- 선택 모델: Extra Trees
- Test 경보 즉시: 7/8, macro F1 0.867
- Test 경보 10분 후: 8/8, macro F1 1.0

10분 시점에는 F1과 F3도 구분했지만 유형별 Test가 2개뿐이고 최대 클래스 확률이 낮았다. 따라서 즉시 결과는 `provisional`, 10분 결과는 `confirmed_candidate`로 정의하고 자동 정비 명령에는 사용하지 않기로 했다.

## 12. 현재 최종 결정

이진 HGB와 온라인 유형 Extra Trees의 2단계 구조를 최종 prototype으로 정리했다. 다만 이진 경보는 전체 재생 오탐 목표를 넘었고 유형 확률은 calibration과 시간적 안정화가 부족하므로 실제 배포는 보류한다. 10분 이진 확정 경보를 계속 목표로 한다면 임계값 조정이 아니라 향후 10~30분 결함을 예측하는 레이블, 더 이른 제어기·물리 센서, 새로운 독립 이벤트가 필요하다.

## 이 프로젝트에서 배운 점

1. 시계열의 행 수와 독립 표본 수는 다르다.
2. 모델은 분 단위로 예측해도 평가는 이벤트 단위로 해야 한다.
3. PR-AUC나 정확도만으로 경보 모델을 선택할 수 없다.
4. 임계값과 persistence는 모델 이후의 운영 하이퍼파라미터다.
5. 빠른 신호와 실제 사용자 알림은 분리해야 한다.
6. 실패한 가설을 수치로 기각하는 것도 중요한 모델링 결과다.
7. 높은 Test 점수보다 외부 검증 전 배포를 보류하는 판단이 더 중요할 수 있다.
8. 유형 정확도와 확률 신뢰도는 다르며, 시간에 따른 예측 안정성도 별도로 검증해야 한다.

## 면접에서 설명할 흐름

> “EDA에서 독립 이벤트가 35개뿐임을 확인해 이벤트 단위 분할과 인과적 전처리를 설계했습니다. Extra Trees 기준선은 68.5분 늦었고 HGB로 지연을 30분까지 줄였지만, 90일 재생에서 장기 오탐 문제를 발견해 배포를 보류했습니다. 10분 이진 탐지는 경보 비용 때문에 기각했고, 느린 유형 분류는 매분 갱신하는 온라인 모델로 다시 설계했습니다. 높은 오프라인 점수보다 평가 누수 방지, 운영 비용, 출력 신뢰도를 함께 보는 의사결정을 배웠습니다.”
